# An evolving investigation, one report

A task and report already explain recurring CPU alert transitions. The report leaves the
underlying CPU workload unconfirmed. Later, the user raises historical replay and says a rolling
restart helped. Record that as a new question and user-provided lead in the existing report,
with replay, traffic cutover and deadlock still hypotheses. Do not create a replay-report suffix.

Next, profiling locates expensive archived-file parsing. Add the inspected selector/window,
sampling limitations and current answer alongside the question. Revise the main finding to
separate the verified execution hotspot from the original alert-threshold mechanism; keep the
earlier alert timeline intact. A restart correlation is not a demonstrated defect.

The user adds an application repository to the source task and asks for code validation.
Reflect that resource addition and the new validation question in the same report. After source
inspection, record the inspected revision, candidate scheduling mechanism and deployment gap;
reconcile the earlier replay/deadlock answer with the actual evidence. The additional repository
is a scope/configuration revision, not a new report identity or proof of deployed behavior.

When asked why profiling was previously omitted, capture the methodological gap and the
resulting coverage correction if relevant to interpreting the investigation. Keep unrelated
editor actions and changes to the investigation-tooling repository out of the incident narrative.
Material agent responses become concise dated answers with evidence/disposition, not uncited facts.

Finally, a task format choice changes. Render the selected companions from the same revised
content and update the delivery inventory. Preserve original evidence windows and historical
accounting; report any unavailable new accounting through its owner. Do not restart the incident,
create another canonical report, or republish externally just because an output format changed.

If an earlier agent already made a separate follow-up, an authorized repair incorporates its
relevant findings into the original canonical report and points the task there. Keep the earlier
follow-up as a historical artifact with its provenance; it is not a second current conclusion.

On transfer, the next agent receives the task, canonical report and declared evidence, without
the chat. It can recover the replay question, profiling answer, source addition and methodological
correction from the continuation record. Its checkpoint shows that deployed-revision mapping
is still open. A missing deployment artifact makes attribution partial even when the report
itself is readable; the next agent completes independent work and identifies that prerequisite.

All names, source identifiers, dates and URLs in this example are deliberately omitted. Private
investigation artifacts retain exact evidence under their own source and disclosure boundaries.
